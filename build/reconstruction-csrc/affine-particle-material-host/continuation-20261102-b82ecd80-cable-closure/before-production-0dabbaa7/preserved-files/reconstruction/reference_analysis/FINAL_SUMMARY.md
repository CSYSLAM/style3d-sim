**算法层面没有秘密，数值验证覆盖了 63%（82/131）。**
接口语义、131 个 kernel 的指令级还原（100% 覆盖、131/131 编译）、数据结构布局、控制流骨架、常量池——全部可读、可编译。

## 3. 数值验证：**82/131 个 kernel 有强证据（63%）**

两套测试，判据一致：**两侧输出逐字节一致，且该 kernel 确实改写过内存**（与运行前快照比较）。

| 套件 | 覆盖 | 结果 |
|---|---|---|
| 人工规格 `run_tests.py` | 34 个 | **23 精确 + 11 容差，0 失败**（随机浮点 + 合法布局 + 真实计数） |
| 自动规格 `auto_ab.py` | 131 个 | **77 个强证据**；41 空转、6 越界、7 超时、**0 加载失败** |
| **并集（不同 kernel）** | — | **82 个（63%）** —— 人工比自动多覆盖 5 个 |

人工规格覆盖：CG 全部算子（两种稀疏格式 × 两种特化）、预条件链、弹簧力、颗粒键、BVH 叶子、AABB、组合算子、`scale_step`、`commit_bonds`、`invert_block_preconditioner`。

### 判据的三次演进（前两次都是错的）

| 轮次 | 判据 | 结果 | 问题 |
|---|---|---|---|
| 19 | 仅比对相等 | 115 | 两边都没干活也算"相同" |
| 22 | 输出非零 | 106 | 输入本来就非零，等于没判 |
| 23 起 | **与初始内容比较（写入 > 0）** | 77（+人工 5 = 82） | 可信 |

### 剩下 49 个为什么验不了（不是工程量问题，是信息缺失）

| 类别 | 数量 | 缺什么 |
|---|---|---|
| `View` / `CableView` 类 | ~20 | **字段语义表**：4 个计数各自约束哪几个指针、元素类型是什么 |
| 稀疏结构类 | ~8 | `row_nnz` 与 `entries` 的长度/索引一致性 |
| 依赖上游输出 | ~21 | 需要前一个 kernel 的真实结果作为输入 |

试过的办法都失败了（记录在 `validate/AUTO_VALIDATION.md`）：共用零池、指针分散到不同区域、
按 `VIEW_LAYOUT.md` 填计数——都因为"计数与数组长度不成比例"而越界或不干活。
真正的解法是把三个 `View` 的字段语义各自重写一遍，那等于重写数据结构定义。

## 4. 修掉的 6 个 bug

| # | bug | 影响 |
|---|---|---|
| 1 | CSR 行偏移误读成 `[2i]/[2i+1]` | 2 个 kernel 公式错 |
| 2 | 第二组求和用了 `add` 而非 `sub` | 256 个 float 符号翻转 |
| 3 | `multiply_matrix_and_reduce` 参数角色与字面顺序相反 | 输出全错 |
| 4 | 测试台 `diag` 缓冲少分配 1728 B | 造成"怎么改都对不上"的假象 |
| 5 | **翻译器 `mov.b32 %r,%f` 当成数值转换** | **61/131 个还原文件** |
| 6 | PTX 提取漏掉 `.global` 常量表 + 翻译器把表当函数占位 | 3 个线缆 kernel 误判为"无法验证" |

前 4 个靠读 PTX 都发现不了，第 5 个连读代码也发现不了——**只有把两边都跑起来比对数值才暴露**。这是 A/B 测试台存在的全部理由。

## 5. 三条已经封死的路（别再重复）

| 路线 | 卡在哪 |
|---|---|
| 用 `VIEW_LAYOUT.md` 构造真实 `View` | `View` 里存在 `{ptr,size}` 成对字段和二级索引，共用零池会导致越界；需要逐 kernel 的数据契约 |
| 给 400 个成员偏移配名字 | `rbx` 并非处处是 `this`（`initialize` 里 `rbx=Model`、`r15=this`）；同一偏移在 `s3dnet`/`cub` 里也存在 → 需要逐函数基址跟踪（Ghidra 级） |
| 追踪 `resize` 的尺寸来源 | 线性回溯 10/35，CFG 前向数据流反而 2/35（φ 爆炸） |

## 6. 能拿到什么 / 拿不到什么

**能拿到**（有产物、可复跑）：

- 接口层：13 类、241 个带文档成员、40+ 默认值
- kernel 层：206 entry / 自研 131，签名+模板实参+寄存器；131 份机械还原（100% 指令覆盖、131/131 编译）+ 32 份人工精修
- 数据层：114 个字段偏移（Config/Model/State/Contact/Control）+ 13 个 View 布局 + 元素尺寸
- 控制流：74 次 launch 顺序、17 个最内层循环、两层迭代计数器、**CG 无收敛判据**
- 常量层：`.rodata` 按引用点提取
- 语义：`Config`/`Model` 的字段名、`Contact` 的 19 个字段使用点

**拿不到**：

- 原始变量名 / 注释 / 行号（无 DWARF，PTX 仅 22 条 `.loc`）
- 未被任何代码访问的结构字段
- 3 个线缆 kernel（`evaluate_cables` 等）的数值验证——**能跑但要构造 CableView**（"libdevice 阻塞"是我的误判，已修）
- Solver 的完整成员布局（需反编译器级分析）
